# AI-Business Command-Center V2

เลขา AI ประจำร้านสำหรับร้านที่ใช้ SML ERP: ส่งรายงานเช้าทาง LINE, ตอบคำถามเรื่องตัวเลขทาง Telegram, เตือนเรื่องที่ต้องรู้, ร่างข้อความให้เจ้าของคัดลอกไปส่งเอง
หลักการ: **AI-BCC เป็นแหล่งตัวเลขเดียว** ผู้ช่วยเรียบเรียงเป็นภาษาคน ไม่คำนวณเอง · อ่านจาก SML อย่างเดียว ไม่เขียนกลับ · ไม่ส่งข้อความหรือทำรายการแทนคน

Fork ของ nextstep-dashboard

- `backend/` Go (chi + pgx) + PostgreSQL 16, เชื่อม SML ผ่าน JavaWS แบบอ่านอย่างเดียว
- `frontend/` Vue 3 + Vite + PrimeVue (หน้า admin และหน้าผู้รับ)
- `backend/deploy/assistant/` ผู้ช่วย (Hermes) พร้อมคำสั่งดูแล · `spikes/hermes/` ผลทดลองและชุดทดสอบจำลอง

## สถานะ (12 ต.ค. 2569)

ใช้งานจริงกับร้านแรก 1 ร้าน ผู้ช่วยตอบได้ทั้ง Telegram และ LINE (ผู้ทดสอบ) ยังไม่เปิดให้เจ้าของร้านใช้

| ส่วน | สถานะ |
|---|---|
| รายงาน 13 ตัว + การ์ด LINE เช้า | ใช้งานจริง |
| Agent API (context, report, compare, delivery, alerts, search, lookup, drafts) | ใช้งานจริง ปิดโดยค่าเริ่มต้น เปิดด้วย `AGENT_API_ENABLED` |
| ผู้ช่วยทาง Telegram (โมเดลตรึงที่ผู้ให้บริการไม่เก็บข้อมูล, ไม่มีเครื่องมือในตัวนอกจากความจำ) | ใช้งานกับ 2 บัญชีทดสอบ |
| เตือน 6 เรื่อง + สรุปเช้า ตั้งด้วยคำพูด ส่งเป็นข้อความสำเร็จรูปไม่ผ่านโมเดล | ใช้งาน (ปลายทางเฉพาะผู้ทดสอบ) |
| ร่างข้อความทวงหนี้ / ร่างรายการสั่งซื้อ | ใช้งาน ร่างเท่านั้น ไม่ส่งเอง |
| ค้นลูกค้า/ผู้จำหน่าย/สินค้า (สำเนาข้อมูลหลักวันละครั้ง) และข้อมูลสดรายลูกค้า/รายสินค้า | ใช้งาน |
| เครื่องมือเปิดร้านใหม่ (`onboard-check`), เก็บหลักฐานเลขผิด (`evidence`), ตรวจก่อนอัปเดต Hermes (`upgrade-check`) | ใช้งาน |
| ยอดขายสุทธิ (ใบขาย + ใบเพิ่มหนี้ − ใบรับคืน/ลดหนี้) พร้อมส่วนประกอบในรายงานขาย | ใช้งานตั้งแต่ 2026-10-09 |
| ร้านที่ 2 (เชื่อมกับ SML จริงของร้านทดสอบเมื่อ 12 ต.ค. ตัวเลขรายวันรวมตรงกับรายงานทั้งเดือน) | ทดสอบอยู่ |
| ตั้งค่าเลขา AI ต่อร้านจากหน้า admin (โมเดล, key ของโมเดล, Telegram, LINE; ค่าลับปิดผนึก) | ใช้งานจริงกับร้านแรก |
| ด่านหน้า LINE (ช่อง LINE กลางส่งต่อไปเลขาของร้านที่ถูกต้อง, เลือกร้านเมื่อมีหลายร้าน) | ใช้งาน ผ่านการลองจริงกับ 2 ร้าน (`LINE_FRONT_GATE`) |
| คำตอบใน LINE: จุดกระพริบระหว่างรอ, รอข้อมูลใหม่ก่อนตอบ, ส่งคำตอบช้าให้เองเมื่อโควตาเหลือ | ใช้งาน |
| สิทธิ์รายคน: ทุกคนที่ถามใน LINE ได้คำตอบตามสิทธิ์ของตัวเอง | เปิดใช้ ยังไม่ได้ลองกับคนที่สิทธิ์ต่างกัน |
| สร้าง/หยุดเลขา AI ของร้านจากหน้า admin (ไม่ต้อง ssh) | พร้อม ยังไม่เคยสร้างร้านใหม่จริง |
| ส่งออกไฟล์ Excel/CSV ทุกรายงาน และอธิบายว่ายอดเปลี่ยนเพราะอะไร | ใช้ได้ทาง Telegram (LINE ส่งไฟล์ไม่ได้) |
| เลขา AI ร้านที่ 2 (ร้านทดสอบ แยกเครือข่าย) | ใช้งาน |
| เมนูปุ่มกดใน LINE: ยอดขายเมื่อวาน / ยอดขายล่าสุด (อ่านสด) / สินค้าใกล้หมด ตอบเป็นการ์ดเดียวกับรายงานเช้า ไม่ผ่านโมเดล · คุยกับเลขา AI ให้คำถามตัวอย่าง (ตั้งด้วย `/app/richmenu`) | ใช้งาน ทดสอบบนมือถือแล้ว |
| ขอตัวเลขล่าสุดผ่านแชต (`refresh`), เตรียมยอดเมื่อวานและวันนี้ล่วงหน้า 07:30 | ใช้งาน |
| ข้อมูลที่ SML ไม่ได้กำหนด (วันครบกำหนดลูกหนี้ จุดสั่งซื้อ ผู้จำหน่าย) เลขาแจ้งผู้ใช้ ไม่เดาแทน | ใช้งาน |
| ร่างข้อความความเป็นส่วนตัว (PDPA) สำหรับร้าน [backend/docs/privacy-statement-draft.th.md](backend/docs/privacy-statement-draft.th.md) | รอเจ้าของระบบตรวจและเติม |
| หน้ารายงานในเว็บดึงตัวเลขล่าสุดเองตอนเปิด (`REPORT_AUTO_REFRESH_ENABLED`) และไม่ใช้ศัพท์เทคนิคกับผู้ใช้ | ใช้งาน ทดสอบบนร้านสินทวีและร้านกระบี่แล้ว |
| กันภาระ SML ของร้าน: ชะลอการอ่านเมื่อร้านตอบช้ากว่าปกติ, ความถี่รายงานหนักต่อร้าน | ใช้งาน |
| LINE ของร้านเอง, ส่งไฟล์ทาง LINE, ปิดระบบเดิม | ยังไม่ทำ |
